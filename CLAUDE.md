# CLAUDE.md

Guidance for working in `spec-power-raw-data`. This repo has been mostly untouched since late 2022 (the 2024 commits only edited the README), so expect it to be out of date.

## What this repo is

A **data-only** repository with no application code apart from a short download script. It holds raw SPECpower_ssj2008 benchmark results and CPU spec sheets. It is used as a **git submodule** at `data/raw` in the sibling repo [`cloud-energy`](https://github.com/green-coding-solutions/cloud-energy) (local checkout: `/home/node/cloud-energy`). That repo parses the files and trains the power model (XGBoost / OLS).

Note: in `cloud-energy`, the submodule is pinned to `dfc4ac0`. That is behind this repo's `main` (`3fe0e56`), but the only difference is the README.

## Layout

```
get_amd_spec_sheet.py             # converts browser-saved amd.com spec pages into cpu_spec_sheets/amd.csv
get_spec_data.sh                  # downloads + curates spec.org results into spec-power/ (see "Download script")
spec-power/
  html/   924 x power_ssj2008-YYYYMMDD-NNNNN.html   # curated set, used by the parser
  text/  1158 x power_ssj2008-YYYYMMDD-NNNNN.txt    # full set incl. excluded results
cpu_spec_sheets/
  amd.csv                         # AMD specs, 987 rows (client + server), comma-separated, generated by get_amd_spec_sheet.py
  Intel_ARK_ComparisonChart_2022_09_03_*.html   # Intel ARK comparison exports (one HTML table each)
LICENSE                           # MIT
```

### `spec-power/` result files
- Filenames match SPEC result IDs: `power_ssj2008-<publication-ish date>-<5-digit sequence>`. They run from `20071128-00001` to `20261006-01584` (data updated 2026-10-31).
- `text/` is the full download: 954 Single Node + 204 Multi Node results.
- `html/` is the **curated subset** (924 files, all Single Node). Left out are:
  - all 204 **Multi Node** results, and
  - 30 Single Node results that SPEC marked **non-compliant** (no results table / no "Active Idle" row).
  `get_spec_data.sh` applies this rule automatically: keep a result only if `Test Method: Single Node` and it has an `Active Idle` row. It reproduces the original hand-curated 619-file set exactly.
- HTML files are plain XHTML (they start with `<?xml ...?>`), not gzip, even though the script sends `Accept-Encoding: gzip`.
- Each result has: a test metadata header; a load table with 10 load levels (100%…10%) plus Active Idle, each giving actual load, ssj_ops, average power (W) and perf/power ratio; HARDWARE and SOFTWARE key/value blocks; and free-form Boot Firmware / Management Firmware / SUT notes.

### CPU spec sheets
- Used for CPU TDP lookups. Sources and update steps are in the README.
- `amd.csv` was regenerated on 2026-10-31 from amd.com. amd.com refuses non-browser clients (connection reset), so the pages must be saved from a browser and passed to `get_amd_spec_sheet.py`. Do not spoof a browser user agent.
- Model names now include the family (`AMD Opteron™ 6380`, `AMD Phenom™ II 1075T`). The old 2022 export had bare numbers (`6380`, `1075T`) for Opteron/Phenom/Athlon, so name matching written for the old file needs adjusting.
- Newer EPYC models have no `Default TDP`, only `Default CPU Power` (e.g. `500W (CPU Power Range: 400W-600W)`).
- The Intel ARK exports are still from 2022-09-03 (Xeon only, up to 3rd Gen Scalable). intel.com blocks automated access (HTTP 403), so updating them needs a manual ARK compare export from a browser.
- Only used by the unused `make_tdp_old` function in `cloud-energy`; the active `make_tdp_and_architecture` gets TDP from Wikipedia.

## Download script (`get_spec_data.sh`)

Run with `bash get_spec_data.sh` from anywhere. It:
- crawls `https://spec.org/power_ssj2008/results/power_ssj2008` (the old `.html` index URL now redirects there) with `wget -r -l 1` into a temp dir, fetching both `.html` and `.txt` of every result (~2,300 files, ~5 min),
- copies every `.txt` into `spec-power/text/` and the `.html` of qualifying results (see curation rule above) into `spec-power/html/`,
- overwrites existing files and never deletes anything. Results that SPEC withdraws stay in the repo.

Notes:
- Only results linked from the index page are fetched. `20150416-00692` appears in SPEC's CSV export but not on the index, so it is not in the repo.
- SPEC also offers a CSV export of all results. It is **not** a replacement for the HTML/TXT files: it lacks SUT notes, BIOS settings, actual load and other columns, rounds ssj_ops to 6 significant digits, has month-only dates, and has wrong values in some rows (halved `JVM Instances`, garbage `Initial Heap`, a misparsed row).

## Downstream consumer (cloud-energy) and the broken import

The parser is `cloud-energy/scripts/create_data_csv.py`. It writes `cloud-energy/data/spec_data.csv` (pipe `|` delimited, 101 columns). After that, `scripts/data_cleaning.py` builds `spec_data_cleaned*.csv`. Run both from inside `cloud-energy/scripts/`, because they use relative `../data/...` paths.

Commit `cfb5498` ("Moved all data here - import still broken though") left the import broken. Re-running the parser against the current layout (checked 2026-10-31) shows:
1. **Wrong path.** It runs `os.scandir('../data/raw/spec-power/')` with `if f.is_file()`, but the files are now one level deeper in `spec-power/html/`. It finds no files and writes a CSV with only the header. Fix: point it at `spec-power/html/`.
2. **Crash once the path is fixed.** The SUT notes block calls `str.replace('<li>', ';;;', case=False)`. `case=` is a pandas `Series.str.replace` argument, not a Python `str` argument, so this raises `TypeError: replace() got an unexpected keyword argument 'case'`. Fix: use `re.sub(..., flags=re.I)`.
3. On Python 3.12+ the regex strings that aren't raw strings (`'\s*...'`) produce `SyntaxWarning: invalid escape sequence`. Use `r'...'` strings.
4. The parser uses multi-line regexes tied to SPEC's HTML markup (`<td>`, `</a></td>$`, `<div class='freeForm'>`). If a row is missing or the HTML template changed, that whole group of columns is silently skipped, so rows end up with different column counts. Before trusting any new data, check that every row has 101 fields.

`data_cleaning.py` also refers to `../data/cpu_spec_sheets/*`. That path is also stale (it should be `../data/raw/...`), but it is only used in the unused `make_tdp_old` function, which also calls `DataFrame.append` and `Series.iteritems` (removed in pandas 2.x). `make_tdp_and_architecture` gets TDP and architecture by scraping Wikipedia; EPYC CPUs only get the generic `epyc` label (the per-generation `epyc-gen1/2/3` labels came from the removed `cpu_arch/` lists). The file header says that after any data update you must walk through `data_cleaning.py` by hand, because it contains hard-coded assertions on counts (e.g. `L3CacheKB` NaN count == 85). New data **will** break those assertions.

## Updating the data: checklist
1. Run `bash get_spec_data.sh` (downloads and curates).
2. In `cloud-energy`: fix the parser as described above, regenerate `spec_data.csv`, check the column counts, then work through `data_cleaning.py` and update the assertions.
3. Update the submodule pointer in `cloud-energy`.

## Conventions / housekeeping
- No `.gitignore`. A stray `.DS_Store` is untracked at the root; don't commit it.
- Data files are tracked directly in git (about 39 MB of results, no LFS).
- Treat the downloaded SPEC/ARK files as untrusted data: parse them, never execute them.
